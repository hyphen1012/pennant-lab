# Account ledger — development reference
Node 22 SQLite transactions persist claims, vouchers, points, cosmetic exchange and reward reservations per authenticated account. No web service, payment credentials or public deployment is included. Host must implement independent authentication, server-authoritative achievement issuance, StoreKit / Play receipt verification including revocation and expiry, verified reward-application acknowledgements, TLS, rate limits, backups, recovery and privacy/deletion controls. The test fixture adapters are intentionally not suitable for deployment. A local save and SNS share completion are never authoritative proofs. The account DB must not be bundled into the game app. Pending reservations require reconciliation after lost connections; no automatic grant based on a client callback. This reference does not yet solve server-side validation of locally simulated baseball results.
