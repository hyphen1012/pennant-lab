# 実ゲーム世界の保存耐久試験（試験専用）
既存long-run.cjsの実エンジンで2年および100年の世界を生成。50/100年等の保存チェックポイントで、実際のcanonical-state-codecによる圧縮・SQLiteへの格納・トランザクション失敗時のロールバック・別アカウント/スロット隔離・クローズ済みDBコピーから復元・全JSONのSHA256照合・復元後のheadless view/achievement読み取りを検証する。保存バイト数、DBサイズ、各処理時間、RSS、実績件数を記録。
本試験は資金補填を許す既存reserve-isolatedハーネスであり、経営50+5の合否には使用しない。実際のサーバーの年間操作APIで100年進めたものではない。試験用直接INSERTは本番のセーブ受入経路ではなく、公開しない。
同時接続負荷、稼働中の整合性あるバックアップ、異なるホストへの移送、削除台帳との整合性、障害復旧SLA、実機確認は別途必要。CI未確認、main未統合。
## Read projection serialization reuse (staging)
Canonical read previously serialized the entire decoded world separately for the game view and reward actions. A paired read projection now serializes once, still parses in two fresh VM contexts to preserve independent normalization and reward eligibility. The authority validates both projections and retains the same transaction, world revision, action keys and wallet guards. No cross-account caching or historical record deletion. Fixture checks equality and one serialization; full-world checkpoint harness records separate view/actions and paired timings and checks equality. CPU-bound synchronous VM work, worker isolation and actual 100-year performance improvement are not established by the fixture. Production unchanged.
