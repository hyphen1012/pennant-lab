# PENNANT LAB — 選手ポートレート・能力ランク配色仕様

**仕様案の確定版（実装前）｜2026-11-24**

## 0. 対象と目的

- チーム→選手確認で見られる「アイコンが二重丸になる」不具合を解消する。
- 一人ひとりを見分けられる、半リアル寄りの**架空選手のスポーツカード風顔ポートレート**に刷新する。実在選手や参考ゲームの画像・顔を複製しない。
- 通常選手の外周は、表示用の対象能力の**単純算術平均**を既存ランク区分で評価した色にする。
- 能力文字色・総合ランク色・アイコン外周色を、同じ正規ランク色テーブルで統一する。
- PARALLEL／STAR／LEGEND／IMMORTAL等の特別選手は、平均能力に優先して**肩書専用の色・模様・ラベル**を使う。
- 暗い紺の既存ゲームUIに適合し、色覚差・低解像度でも識別できるよう形状と文字ラベルを併用する。

> 参考の「パワプロ」画像から読み取れる色系統に近づけた**PENNANT LAB独自の近似HEX指定**。画像の圧縮・画面表示差があるため、元ゲームの公式色コードや厳密一致を断言するものではない。参考画像ではA=ピンク、B=赤、C=橙、E=緑、F=水色。Dは画面に写っていないため、CとEの間を自然につなぐ黄緑とする。

## 1. 能力ランク・共通HEX

| ランク | 基礎値 | 表示色（文字・枠） | 意図 |
| --- | --- | --- | --- |
| SS | 100 | `#DCE3EB` | シルバー。明るい面・薄い陰影で金属感 |
| S+ | 99 | `#F6D46A` | Sの金色系を継承。文字 S+ で差別化 |
| S | 90–98 | `#F1C54B` | 現状より濃淡のあるゴールド |
| A | 80–89 | `#F5B1B8` | 明るい暖色系ピンク（紫みを除く） |
| B | 70–79 | `#E85062` | 赤／ローズレッド |
| C | 60–69 | `#E8AA3F` | 橙／アンバー |
| D | 50–59 | `#A1CF47` | 黄緑 |
| E | 40–49 | `#43C86B` | 鮮やかな緑 |
| F | 0–39 | `#41B6E6` | 水色／シアン |

- 数値のランク境界は**既存ゲームの `grade(v)` に一致**。既存のS+ 99とSS 100の区別を保持する。
- ゴールド・シルバーは、**文字の色は上の指定をベース**にし、枠にはごく控えめなグラデーションを使用できる。グラデーションは上記色の色相を維持する。
- 全体の既存 `gradeBriefColor`, `rankColor`, ランク付き能力値と、監督のS〜F表示は**1つのランク定義関数**を参照する。現在の `grade` と色判定閾値がずれている点を修正する。
- 99のS+、100のSSはそれぞれ明示表示。平均から色を求める際は、丸めた平均を同じ区分に当てる。
- 色が背景に埋もれる場合は外側の細いダークアウトラインや影でコントラストを補い、**ランク色そのものは変えない**。

## 2. 通常選手の平均能力→リング色

### 対象と計算（表示中の5項目の同じ重み）

現在のチーム一覧に出ている5つの能力を基準にする：

- 野手：巧打（`contact`）、長打（`power`）、走力（`speed`）、守備（`defense`）、精神（現行表示は `talent`）
- 投手：球威（`stuff`）、制球（`control`）、変化（現行表示は `round((stuff+control)/2)`）、体力（`stamina`）、精神（`talent`）
- `平均 = Math.round(5項目の合計 / 5)`。この平均値を上記の共通ランク表に当てる。
- **ポジション別の使わない能力を0として含めない**。投手の打撃値0などは平均から除外。
- `mental/talent` を分離し、変化球の独立ステータスを実装する将来更新では、能力表と平均の対象を同時に見直す。現時点では、ユーザーが**実際に見ている5項目と枠の色が対応**することを優先する。
- 欠損値は無理に0で扱わず、旧セーブは既存の補完処理を経て値を取得する。値が未判明のスカウト候補は実際の能力平均を推測させる枠色を表示しない。

**例：** 5項目 `63,75,94,73,58` は平均 `72.6→73`、Bランクなので**赤 `#E85062`**の枠。

**注意：** 現行の総合値 `rating(p)` は野手5項目の単純平均とは異なる「重み付き値」で、投手も3項目を異なる重みで評価している。下部の「総合数値バッジ」は従来の `rating(p)` を維持し、**枠色だけを上記の5項目平均で決める**。数値と枠色の意味はツールチップ／選手詳細で区別する。

## 3. 特別選手の専用カラー

色の優先順位：**未公開の能力保護 ＞ 特別肩書（存在すれば） ＞ 通常ランク色**。

| カテゴリ | 名前文字の主色 | 枠の第2色 | 識別要素 |
| --- | --- | --- | --- |
| PARALLEL | `#B28AFF`（紫） | `#6951CE` | 紫の二重光沢線＋PARALLELタグ |
| STAR | `#FFE070`（黄／金） | `#D49F2E` | 星マーク・微細な星模様＋STARタグ |
| LEGEND | `#FF6175`（紅） | `#8D2840` | 赤の縦スリット／紋章＋LEGENDタグ |
| IMMORTAL | `#EBF3FF`（白銀） | `#151D30`（黒曜） | ごく細い虹彩ライン＋IMMORTALタグ |
| 再来選手 | `#6ED7C0`（青緑） | `#267D72` | 還る矢印／系譜の意匠＋再来タグ |
| 転生選手 | `#84B4FF`（青） | `#365DAF` | 二重軌道・継承の意匠＋転生タグ |
| 輪廻転生 | `#E7E7FC`（薄紫銀） | `#3D315C` | 金の細い円環・専用紋章＋輪廻転生タグ |

- **PARALLEL紫、STAR黄・金、LEGEND赤、IMMORTAL白銀＋黒曜＋虹彩**は従来のゲーム設計書と整合する基本系統。
- 再来／転生／輪廻転生のHEXとパターンは今回の実装準備上の**提案値**。正式イベント画面制作時に細部は調整可能。
- **特別選手は名前色と外周リング色を肩書から一括決定し、通常の平均能力で上書きしない**。通常の選手は名前白色のまま。
- STARの金と通常Sの金、LEGENDの赤と通常Bの赤は重なり得る。**専用タグ・模様・アイコン形状を必須**にし、色だけで判別しない。
- IMMORTAL・輪廻転生が**未入団**の状態は既存の秘匿仕様を優先：顔はシルエット、能力は全項目「???」、値や平均が推測できる枠やバッジを使わない。カテゴリーが公開されている場合のみ専用の意匠と文字ラベルを示す。
- 所属タイトル（MVP、本塁打王等）の表彰用アイコンはこれとは別。PARALLEL等の**肩書リングを賞の枠色で置き換えない**。

## 4. 顔ポートレート仕様

**目標：** 現行の簡易SVG（4種類の肌色、5種類の髪色、顔輪郭ほぼ共通）から、細部を見分けられる**半リアルなオリジナルスポーツカード風の架空顔**へ変更。

- 基本形：顔と肩が入る**頭部〜胸上のバストアップ**。スマホの直径40px表示でも区別が付くよう、強い輪郭と十分な目鼻のサイズを保つ。
- 差分：顔型（丸・面長・角張り・細面）、髪型（短髪・分け目・くせ毛・刈り上げ・薄毛等）、眉（太さ／角度）、目（形／間隔／まぶた）、鼻、口、ひげ／無精ひげ、眼鏡、肌の明暗、若手・ベテランの年齢感、ユニホーム配色。
- パターン数は**少なくとも各パラメータ4〜8種類**、組み合わせで数千以上。顔の個性が似すぎる場合は、髪型・輪郭・眉に優先して差を付ける。
- オリジナル顔の生成は`player.id`と必要なら`appearanceSeed`から**決定的に**行う。セーブロード・年齢変化・チーム移籍・複数画面で同じ人物の顔が勝手に変わらない。
- 年齢差は元顔の識別性を壊さない軽微な陰影／しわだけ。監督も同じ外観基盤で別バリエーションを適用。
- MVP・観戦・編成・チーム・スカウトなど、**1つの共通顔レンダラー**を使う。端末によって顔が違う状態を避ける。
- 初期実装はSVGベクターを推奨（通信不要・低負荷・40〜80pxにも対応）。より写実寄りのアセットに発展させる場合も顔IDとの対応を保持。
- 実在選手の顔・写真・実名・参考ゲームのイラストは転用しない。

## 5. UIコンポーネント構造（二重リング防止）

```text
PlayerIdentity
├─ PlayerPortrait (ひとつだけ描画)
│  ├─ Artwork       … 顔・肩のSVG。枠は一切描かない
│  ├─ OuterRing     … ランク色 または 肩書専用リング、1本だけ
│  ├─ OverallBadge  … 従来の総合数値バッジ（外周リングではない）
│  └─ TitleMark?    … 特別選手の小さな肩書ラベル／紋章
└─ PlayerName       … 通常は白、特別選手なら肩書色
```

- **二重丸の原因**：現行の`portrait(p)`は`.avatar`に外枠を描き、内部で呼ぶ`faceMini(p)`も`.face-mini`に外枠を持つ。現行コードで2つの円が重なっている。
- 新APIでは`renderFaceArtwork(p)`（枠なしSVGのみ）と`renderPlayerPortrait(p, size, context)`（**唯一の枠・数値バッジ**）を分ける。小型の`faceMini`は共通ポートレートを小さく表示する入口として使い、別の内側リングを追加しない。
- 1つの外周枠だけを描く。能力ランクの変化・特別選手の肩書変更があっても**顔レイヤーには色依存の枠処理を入れない**。
- 従来の投手ピンク／野手青の区別を示す必要がある場面では、リングではなく**ユニホーム・ポジションバッジ・説明文**で識別。ユーザー指定の枠色優先規則を守る。
- 小型24px・標準40〜56px・大型72〜88pxで共通レイアウトを使用。小型では総合数値バッジを省略できるが、顔・リングの重複はさせない。
- 選手リスト、選手詳細、打順/ローテ、交換モーダル、試合実況、年間表彰、監督候補に同じコンポーネントを適用。
- 空き枠や未知のスカウト対象は中立色のシルエット／?を使用し、実能力・顔の秘匿を破らない。

## 7. 実装完了の受入基準

1. チーム→選手確認で**顔の枠は一重**。顔・外輪・数値バッジが別々の責務で描画される。
2. 顔は複数選手を並べたとき容易に識別でき、セーブ／ロードや編成画面との往復で変化しない。
3. Aピンク・B赤・C橙・D黄緑・E緑・F水色、S金・SS銀がすべての能力表示で一致し、`grade`と色に閾値の不整合がない。
4. 通常選手の枠は**5項目平均**に対応する。野手・投手とも実例を使ってテストし、0の未使用能力を平均に混入させない。
5. 例の `63,75,94,73,58` は平均73→B赤。**総合バッジの値は従来どおり**で勝敗計算も変化しない。
6. 特別選手の名前と外枠は常に肩書色、同じ色の通常S/ B選手とタグ・模様で判別できる。
7. 未入団IMMORTALと輪廻転生は「???」とシルエットを維持し、平均能力の色から素質を推測できない。
8. 12球団各選手、編成・試合結果・選手詳細・監督候補で同じ顔ID／枠テーマが使われる。
9. Android狭幅（360px程度）でも名前・顔が重ならず、縦横スクロールの新たな不具合を起こさない。
10. 試合エンジン・旧セーブv2・自動進行・一時停止・本部へ戻る・ゲーム記録が維持され、自動テストが合格する。

## 8. 実装順序（予定）

1. 共通ランク・色関数を統一（能力値表示を一括差し替え）。
2. ポートレートの二重枠除去・外周リング管理の一本化。
3. 5項目平均と通常ランク色連動。
4. 顔SVGの半リアル化とID固定差分。
5. 特別選手カラーの優先順位・タグ・秘匿処理の基盤を実装。
6. Android実機での文字・色・重なりと長期進行の回帰検証。

**実装状況（v0.8.5／2026-11-24）：** 主要な表示仕様を実装済み。チーム一覧の外周を一重化し、5項目平均リングと共通ランク色、同じ顔SVGレンダラーによる選手詳細・編成・試合ハイライト・監督の表示を導入。顔の外見は選手IDまたは任意の `appearanceSeed` に固定し、年齢に応じた軽微な陰影を追加。特別選手の名前と枠色、未公開能力に対するシルエット表示は共通レンダラーで対応。

**まだ実装していないもの：** 特別選手そのものの生成・ドラフト・肩書を付けるゲームルール、現在存在しないスカウト候補からの秘匿フラグの自動設定、Android実機による写真寄りの顔の品質調整。能力平均以外の総合数値と試合計算、セーブ形式は変更していない。

## 9. v0.9.12 配色調整（ユーザー指定）
通常AランクのマゼンタはPARALLELのイメージと重なるため廃止し、暖色系の淡いピンク `#F5B1B8` に統一。通常Bの赤 `#E85062` とは明度で差別化する。PARALLELの専用紫 `#B28AFF` / `#6951CE` は変更しない。能力文字・全画面の外周リングに共通適用し、数値・平均・ランク閾値には変更を加えない。
